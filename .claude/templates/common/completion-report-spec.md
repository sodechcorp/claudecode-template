# 完了報告フォーマット — 詳細仕様

Salesforce 環境（Sandbox／本番）の状態に関わる完了報告（保守課題対応・デプロイ・設定変更・リリース準備等）に適用する。ドキュメント生成のみ・コード調査のみ等、組織環境への反映を伴わない完了報告は対象外（CLAUDE.md Output Format の他行を使う）。

## 必須 5 項目

1. **確認環境**: 対応・検証を行った Sandbox エイリアス／環境名（複数環境をまたぐ場合は全て列挙）
2. **本番反映状況**: 「済」「未」のいずれかを明記する。未反映の場合は目立つ形（太字等）で明示する。環境を特定しない曖昧な言い切り（「反映しました」「修正しました」等）は禁止
3. **残作業**: 本番反映・お客様確認・ドキュメント更新等、未完了のタスクを箇条書き。無ければ「残作業なし」と明記する（省略しない）
4. **確認方法**: 「誰が（担当者・ロール）→ どの操作（Login As／画面遷移／実行コマンド）→ どうなれば OK（期待結果）」の3点セットで記載する。目視確認が必要な場合はレコード URL・操作手順を含める（[visual-confirmation-handoff.md](visual-confirmation-handoff.md) の様式を再利用してよい）
5. **未確認事項**: 時間・権限・環境的制約で確認できなかった点を明記する。無ければ「未確認事項なし」と明記する

## 見出し動詞に環境を必ず付ける（Sandbox 完了 ≠ 完了）

本番反映を伴う課題は、Sandbox での対応完了は「暫定完了」であり「完了」ではない。完了報告の見出しは環境を含む表現で書く。

| NG | OK |
|---|---|
| `## {issueID} 対応完了` | `## {issueID} {alias} Sandbox で対応完了（本番未反映）` |
| `## 修正完了しました` | `## Sandbox 検証まで完了。本番反映は未実施` |

本番まで反映済みの場合のみ、見出しで単独の「完了」と書いてよい。

## 着手時に Done の定義を確認する

保守課題着手時（`/backlog` Phase 0 の接続組織確認時等）に、今回の対応の完了スコープ（= Sandbox での実装・検証・お客様確認までを完了とし、本番反映は別途人が実施する）をユーザーに一度提示する。スコープに認識差異があればここで指摘してもらい、完了報告後に初めて発覚する事態を防ぐ。

## 適用対象

組織環境への反映（デプロイ・データ変更・設定変更）を伴う完了報告が対象。dry-run のみ・永続化なしの検証結果報告（例: `backlog-tester.md` のスモーク確認完了報告。dry-run デプロイのみで Sandbox へのコード永続化を行わない）は対象外— PASS/FAIL 判定の報告で足りる。

- `backlog-releaser.md` Step 4（完了報告・実装済み）
- 今後 Salesforce 環境へ実際に反映する完了報告を新設・改修する場合は本フォーマットに従う

> **見出しに環境を明記する慣行**（上記「見出し動詞に環境を必ず付ける」）は `release-preparer.md`（本番リリース準備の完了報告で「本番リリース準備 完了」と明記）が既に体現している。ただし同ファイルの本文構成（サマリー／引き渡し／重要）は本仕様の5項目ラベルとは異なる独自形式であり、5項目への準拠を主張するものではない。
