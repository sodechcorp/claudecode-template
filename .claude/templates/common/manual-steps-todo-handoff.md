# 手順書の Todo 化・逐次ハンドオフ（共通仕様）

人間が実行する複数ステップの手順書（`release-plan.md` の ② リリース実行 / `manual-operation-steps.md` の操作ステップ 等）をユーザーに渡すときの標準フロー。**全文を一度に貼って終わりにしない**。TodoWrite でステップを管理し、1個ずつ提示 → 実行結果の報告を待つ → 次のステップ、を繰り返す。

## 適用対象

- `/release`（`release.md` Step 4）: `release-preparer` が生成した `release-plan.md` の「② リリース実行」内 `### Step N: ...` 各項目（+ 管理画面手動操作の記載があればそれも1項目として追加）
- `/backlog`（`backlog.md` Phase 6）: `backlog-releaser` が管理画面直接操作（2b）を選んだ場合に生成する `manual-operation-steps.md` の「操作ステップ」内、番号付き各項目

チェックリスト形式の事前/事後確認（release-plan.md の ① リリース前チェック・③ リリース後チェック、manual-operation-steps.md の「確認事項」）は対象外。これらは実行順序を強制しない確認事項の一覧のため、該当セクションをそのまま一度に提示してよい（1項目ずつに分解しない）。

## サブエージェント側の責務（重要な変更点）

手順書は今まで通りファイルに生成する。**ただし完了報告に全文を含めない**。ファイルパスと構成（ステップ数・管理画面操作の有無等）の概要のみ言及する。全文提示・Todo 化・逐次進行はコマンド本体（メインスレッド）側の責務であり、サブエージェントの完了報告テキストで代替しない。

## コマンド本体（メインスレッド）側の手順

1. サブエージェントの完了報告を受け取ったら、生成された手順書ファイルを Read する
2. 「適用対象」の番号付きステップを抽出し、TodoWrite でタスク化する（1ステップ=1 Todo。ステップ数は手順書の内容に応じて可変）
3. 先頭の未完了ステップを `in_progress` にし、**そのステップの内容（実行するコマンド・確認事項）のみ**をチャットに提示する。他の未着手ステップの内容は見せない。末尾に「実行結果を教えてください」と一言添える
4. ユーザーの応答を待つ:
   - **実行完了の報告** → 該当 Todo を `completed` にし、次のステップを `in_progress` にして提示する
   - **エラー・質問** → その場で回答する（手順書・関連ファイルを再確認してから答える）。Todo は進めず同じステップに留まる
   - **中断・持ち越し宣言** → 現在の Todo は未完了のまま残し、残りステップを保留した旨を一言添えて終了する
5. 全ステップが `completed` になったら、後続の案内を提示する:
   - `/release`: release-plan.md「デプロイ完了したら教えてください」の案内（release-preparer.md Phase 7 起動条件）
   - `/backlog`: 管理画面操作手順書に紐づく完了報告の残作業チェック（backlog-releaser.md §2b 参照）

## 適用しない場面

- ステップが1件のみの手順（分解の意味がないため、そのまま提示してよい）
- ユーザーから「まとめて出して」「全部見せて」等の明示的な要望があった場合はそれに従う（本仕様はデフォルト挙動）
