# 手順書の Todo 化・逐次ハンドオフ（共通仕様）

人間が実行する複数ステップの手順書（`release-plan.md` の担当者作業 / `manual-operation-steps.md` の操作ステップ 等）をユーザーに渡すときの標準フロー。**全文を一度に貼って終わりにしない**。TodoWrite でステップを管理し、1個ずつ提示 → 実行結果の報告を待つ → 次のステップ、を繰り返す。

## 適用対象

- `/release`（`release.md` Step 4・Step 5）: `release-plan.md` の担当者が実行・確認する項目すべて。**① の【担当者】→ ② の `### Step N: ...` 各項目〔+ 管理画面手動操作〕を先に渡し、③ の担当者確認はデプロイ完了後に Claude のリリース後確認（Phase 7）が終わってから渡す**。Claude が read-only で確認済みの項目・Claude が実行する項目（通常経路の ② Step 1 のバックアップ最新確認、③ の Claude の確認〔画面確認は `prod-ui-verifier`〕）は Todo にせず Claude が実施して結果だけ伝える
- `/backlog`（`backlog.md` Phase 6）: `backlog-releaser` が管理画面直接操作（2b）を選んだ場合に生成する `manual-operation-steps.md` の「操作ステップ」内、番号付き各項目

`/backlog` の manual-operation-steps.md の「確認事項」（チェックリスト形式）は対象外で、一度に提示してよい。`/release` は ①〜③ の担当者項目をすべて1つずつ渡す（前の結果で次の内容が変わりうるため）。

## サブエージェント側の責務（重要な変更点）

手順書は今まで通りファイルに生成する。**ただし完了報告に全文を含めない**。ファイルパスと構成（ステップ数・管理画面操作の有無等）の概要のみ言及する。Todo 化・逐次提示はコマンド本体（メインスレッド）側の責務であり、サブエージェントの完了報告テキストで代替しない。

## コマンド本体（メインスレッド）側の手順

1. サブエージェントの完了報告を受け取ったら、生成された手順書ファイルを Read する
2. 「適用対象」の番号付きステップを抽出し、TodoWrite でタスク化する（1ステップ=1 Todo。ステップ数は手順書の内容に応じて可変）
3. 先頭の未完了ステップを `in_progress` にし、**そのステップの内容（実行するコマンド・確認事項）のみ**をチャットに提示する。他の未着手ステップの内容は見せない。末尾に「実行結果を教えてください」と一言添える
4. ユーザーの応答を待つ:
   - **実行完了の報告** → 該当 Todo を `completed` にし、次のステップを `in_progress` にして提示する
   - **エラー・質問** → その場で回答する（手順書・関連ファイルを再確認してから答える）。Todo は進めず同じステップに留まる
   - **`/backlog` で「Sandbox では行えない・行う意味がない」の報告**（Sandbox に対象のユーザー・ライセンスが無い、Sandbox で検証済み等）→ 該当する Todo（同じ対象への続きのステップを含む。「全部」なら残り全て）を `completed` にして次へ進む。飛ばすときは「今は本番で操作せず、`/release {issueID}` の手順書（変更前の値の記録・ロールバック手順付き）で行ってください」と一言伝える
   - **`/release` の場合の追加手順**: 報告を受けるたびに、結果（日時・実行したこと・報告内容・次の対応）を `docs/logs/{issueID}/release-log.md` に1行追記する。そのうえで**次のステップの内容を結果に合わせて組み立て直す**（手順書の固定文をそのまま出さない）。例: dry-run でエラー → エラー文を読んで原因を切り分け（release-plan.md「dry-run/デプロイが失敗した場合の切り分け」）、本番デプロイに進めず対処のステップを出す／Step 3 のデプロイ失敗 → 本番は変わっていないため dry-run と同じ切り分けに進む／Step 3 成功後の Step 3b（削除）失敗 → ロールバックか削除だけ再実行かを提示する／削除デプロイが不要になった → Step 3b を飛ばす
   - **中断・持ち越し宣言** → 現在の Todo は未完了のまま残し、残りステップを保留した旨を一言添えて終了する
5. 全ステップが `completed` になったら、後続の案内を提示する:
   - `/release`: ① ② が終わったら「本番デプロイが完了したら教えてください」と案内する（release-preparer.md Phase 7 の起動条件）。③ は Phase 7 と画面確認（`prod-ui-verifier`）の後に同じ方式で渡す
   - `/backlog`: Sandbox で操作したステップがあれば manual-operation-steps.md の「確認事項」を一度に提示する（飛ばしたステップだけに関わる項目は除く）

## 適用しない場面

- ステップが1件のみの手順（分解の意味がないため、そのまま提示してよい）
- ユーザーから「まとめて出して」「全部見せて」等の明示的な要望があった場合はそれに従う（本仕様はデフォルト挙動）
