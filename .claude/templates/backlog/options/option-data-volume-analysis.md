# option-data-volume-analysis

## 何をするか

変更対象オブジェクトのデータ件数・大量データ時の影響を評価する。

## 実行手順

1. 変更対象オブジェクトのデータ件数を本番で確認する（`option-prod-select-reference` 準拠・許可不要）:
   ```bash
   sf data query --query "SELECT COUNT() FROM {ObjectName__c}" --target-org {prod-alias} --json
   ```
   本番参照が実施できない場合は Sandbox 件数を**参考値として補足するのみ**とし（Sandbox のレコードはテストデータで、本番の件数・入力傾向を表さない）、影響評価は `[要確認: 本番データ未確認]` を付けて断定しない。
2. 件数に応じた影響評価を行う:
   - **〜1000件**: 通常処理で問題なし
   - **1万件〜**: SOQL の WHERE 条件・インデックスの有無を確認
   - **10万件〜**: バルク処理・バッチ対応の必要性を検討
   - **100万件〜**: 大量データによるガバナ制限・タイムアウトリスクを精査
3. 今回の変更（SOQL 追加・フィールド追加・処理追加）が大量データ環境で問題を起こすか評価する

## 出力

investigation.md に追記:

## データ量分析

- {オブジェクト名}: 本番の件数 {N} 件 / `[要確認: 本番データ未確認]`（Sandbox の参考値 {N} 件）
- 影響評価: 問題なし / 要注意（{理由}） / 要バッチ対応
- 推奨対応: {なし / SOQL 最適化 / バルク対応 / バッチ処理}
