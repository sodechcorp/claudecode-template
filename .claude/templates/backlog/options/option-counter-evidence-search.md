# option-counter-evidence-search

## 何をするか

現在の原因仮説に矛盾する反証を積極的に探す。確証バイアス（仮説を支持する証拠だけ集める傾向）を防ぐ。

## 実行手順

1. 現在の採用原因仮説を 1 文で明示する（例: 「FLS 設定が原因でフィールドが表示されない」）
2. この仮説が**間違いだとしたら**、どんな証拠が見つかるはずかを考える:
   - 「FLS が原因なら、その項目の参照権限だけが違うユーザーでは症状が出ないはず」→ そのユーザーでも同じ症状が出るなら FLS 以外の原因がある
3. 反証を探す具体的なアクションを実行する:
   - 別ユーザー・別プロファイルとの権限・共有の差を sf CLI で比べる（ObjectPermissions・FieldPermissions、`UserRecordAccess` を UserId と RecordId で SOQL。別ユーザーとしての画面操作はバグなら Phase 1.6 が行う）
   - 別オブジェクト・別レコードでの動作確認
   - 条件を変えた場合の動作確認
   - コードの他の分岐・フローでの確認
4. 反証が見つかった場合:
   - 仮説を修正または破棄する
   - 新しい仮説を立てて同じプロセスを繰り返す
5. 反証を探して見つからなかった場合:
   - 仮説の尤度を上げて採用する
6. 2. の証拠を 3. のアクションで観測できなかった反証（別ユーザーとしての画面操作が要る・使った手段で元の条件の症状を出せていない等）は「反証なし」とせず「未試行（{理由}）」と記録し、尤度を上げる根拠にしない

## 出力

investigation.md「## 根本原因 / 要件の本質」の末尾（次の「## 」見出しの前）に追記（仮説を直した・破棄した・新しく立てた・尤度を変えたときは「### 原因仮説（多角分析）」の表と採用仮説も直す。新しく立てた仮説は続きの H 番号で表の末尾に足し、破棄した仮説は行を消さず、反証の列に反証を書いて尤度を「低」にする）:

### 反証探索の結果

- {探した反証}: 反証なし（H{N} の尤度: {高/中/低}）/ 反証あり（{内容}→H{N} を修正: {修正後仮説}、または H{N} を破棄。新しく立てた仮説: H{M}〔なければ「なし」〕）/ 未試行（{理由}）
