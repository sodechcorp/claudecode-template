# option-lineage-map（組織の地図で影響を引く）

## 何をするか

`force-app/main/default` から作る「組織の地図」（`.lineage/`）で、変更対象を**使っている部品**と、オブジェクトを**保存すると動くもの**を数秒で引く。Grep の前に引き、Grep は地図に無いものの補完と裏付けに使う。

地図に入っているもの（詳細は [scripts/python/sf-lineage/README.md](../../../../scripts/python/sf-lineage/README.md)）:
- 部品 → 項目・選択肢の値・部品の参照: 項目（数式・積み上げ集計・参照の絞り込み・連動）・入力規則・リストビュー・レコードタイプ・ページレイアウト（項目・アクションの配置）・Lightning ページ・パス・レポートタイプ・レポート・アクション・ワークフロー（項目自動更新・メールアラート）・承認プロセス・割り当てルール・重複ルール・権限セット・プロファイル・リード変換・フロー・メールテンプレート・カスタムメタデータのレコード
- Apex の項目の読み書き・DML（変数の型の宣言から追う）、LWC・Aura・VF の参照
- 値を写す連鎖（フロー・Apex が項目の値を別の項目へ入れる）と、部品の呼び出しの連鎖（画面部品 → それを埋め込むフロー → それを呼ぶアクション → それを置くレイアウトなど）
- 保存時の暗黙の連鎖（保存で動く入力規則・トリガー・レコードトリガーフロー〔保存前・保存後・順番〕・ワークフロー・重複ルールと、書き込み・積み上げ集計による親や別オブジェクトへの波及）。項目自動更新は、ワークフローのルールから呼ばれるものだけを「保存で動く」に入れ、承認プロセスから呼ばれるもの（申請・承認・却下・取り下げで動く）は別に出す

## 使う場面

| 場面 | 引くもの |
|---|---|
| Phase 1 investigator Step C (2) 3.（保存時に連動する処理・書き込み元の名前を挙げる） | `who <変更しそうな項目・部品>`・`save <更新するオブジェクト>` |
| Phase 3 backlog-planner B-1 0.（スコープ内の全量読込の列挙） | 決定方針の変更対象で `who`・`save` |
| Phase 3.5 regression-guard Step 1・3（変更対象の依存先・副作用） | 変更対象の項目・部品で `who`、更新するオブジェクトで `save` |

## 手順

プロジェクトのルートで実行する（地図が無いか force-app より古いときは、自動で作り直してから引く）:

```bash
python scripts/python/sf-lineage/lineage.py who Obj__c.Field__c [Obj.Field ...] [LWC:名前] [クラス名] [フロー名]
python scripts/python/sf-lineage/lineage.py save Obj__c
python scripts/python/sf-lineage/lineage.py label 表示ラベルの一部     # API 名が分からないとき
```

- 対象の書き方: `Obj__c.Field__c` ／ `LWC:名前`（Aura も）／ `QuickAction:Obj.名前` ／ `EmailTemplate:フォルダ/名前` ／ `EmailAlert:Obj.名前` ／ `Label:名前`（カスタム表示ラベル）／ クラス名 ／ フロー名 ／ オブジェクト名。選択肢の値は `--value 値`
- 出力の区分: 「この対象に書き込む部品」／処理（2段目まで全部）／処理の3段目以降／全項目・どの項目か不明の読み書きをする部品（全項目の複製・項目名を変数で渡す処理）／画面・帳票／権限・レコードタイプ／確度が低い候補／テストクラス。画面・帳票などは先頭8件だけ出るので、全部見るときは `--all`
- 各行の `[N段]` は辿った段の数、`← …` は経由（数式・積み上げ、値を写した先、呼び出し元）、`(mid)`・`(low)` は確度

## 守ること

- **地図は候補。** investigation.md・implementation-plan.md・validation-report.md に「影響あり／なし」を書く前に、該当するファイル・行をソースで確かめる（`refs.jsonl` にファイルと行がある）
- **有効／無効は組織で確かめる。** 地図は最後に取得した force-app の写しから作る。「無効だから影響なし」は [option-flow-trigger-trace.md](./option-flow-trigger-trace.md) 手順2 で組織に問い合わせてから
- **確度が低い候補**（同名の項目の出現など）は、確かめてから使う。確かめずに影響ありとも影響なしとも書かない
- 引いた結果は、記録先の節に1行で残す: `地図（{作成日時}）: 処理 {N}（{主な名前}）・画面帳票 {N}・権限 {N}・保存で動くもの {N}`

## 地図に無いもの（Grep・組織で補う）

| 無いもの | 補い方 |
|---|---|
| 取得していない部品（レポートの本体など。force-app に無いものは地図にも無い） | 取得範囲を確かめる。本番・組織の参照は `sf data query` 等で |
| 本番だけにある部品・取得の後の変更 | 対象組織で確かめる（option-org-drift-check） |
| 管理パッケージの中身 | 名前空間付きの部品は中身が見えない。提供元の資料で |
| 文字列で組み立てる SOQL の項目・項目名を変数で渡す処理の具体的な項目 | 「全項目・どの項目か不明」の区分に出た部品を読んで確かめる |
| カスタム設定の値・データ・件数 | 組織で確かめる |
| 組織の外（外部システム・帳票ツールのテンプレート） | 資料・担当者 |
