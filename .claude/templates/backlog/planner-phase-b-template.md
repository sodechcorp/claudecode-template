## テスト観点（軽量列挙）

investigation.md の Step G に記載されたテストシナリオを元に、テスト観点を列挙する。
詳細な実行手順・期待結果・判定方法は `/test {issueID}` が Phase B で展開するため、ここでは **観点の網羅性** を確保することに集中する。

> 課題種別ごとに当てるべき観点の指針: [test-pattern-map.md](test-pattern-map.md)

| No | 確認観点 | 種別 | タイミング |
|---|---|---|---|
| TC-001 | | SOQL | 実装後 |
| TC-002 | | AnonApex | 実装後 |
| TC-003 | | UI | 実装後 |

※ **列数は必ず 4 列（No/確認観点/種別/タイミング）**。
※ No は `investigation.md` のテストシナリオの TC番号を引き継ぐ（新規観点のみ続き番号で追加）。証跡ファイル名と一致させるため再採番しない。
※ **「確認観点」列の書き方**: `/test` Phase B の `test-spec-builder` が展開するときの起点になる。自然文1文で書き、オブジェクト・項目はラベル（日本語表示名）を先頭に（API名は括弧補助のみ）。要求充足観点は `①` `②`…、回帰観点は `回帰` を先頭に付す。
※ 種別 = `SOQL` / `AnonApex` / `UI` / `メタ確認` / `ファイル確認`（`ApexTest` は使用禁止。テストクラスの回帰確認は `/backlog` Phase 5/6 で実施済みのため `/test` では扱わない。権限・FLS差分は `UI: Login As` ＋ `SOQL/AnonApex` に振る）
  - **種別の選び方（積極ルール）**: 「画面の表示・レイアウト・画面フロー（遷移）・LWC・操作感、および『表示される/されない』の確認」は**必ず `UI`**（スクショで見せる）。「レコードの中のデータ値・件数だけを確認すればよい」観点は `SOQL`/`AnonApex`（テキスト確認で十分・UI に上げない）。
  - `AnonApex`: データ作成・Flow 起動・ビジネスロジック直接実行が必要なケース（結果確認がデータ値のみなら `SOQL` と併用）
  - `UI`: 画面の見た目・レイアウト・画面フロー・LWC・操作、表示有無の確認は全てここに振る（「できることは全部やる」は種別の網羅性の話であり、画面観点まで SOQL/AnonApex に倒す意味ではない）
※ タイミング = `実装前` or `実装後`（実装前観点は Before 証跡として Phase 3 末尾で採取）
