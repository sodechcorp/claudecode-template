Salesforce の組織の地図を Neo4j で見る（貼るだけの Cypher 集）

■ Cypher とは
  Neo4j に「この形のつながりを探して、図にして」と頼むための言葉です（SQL のグラフ版）。
  覚える必要はありません。下の枠の中を丸ごと貼って、▼ の行の '…' の中だけ変えます。

■ 使い方
  1. 作業環境の Neo4j を起動する（<作業環境>\start-neo4j.cmd。作業環境は DDD-Ontology の原本から new-onto-env.cmd で作る）
  2. ブラウザで 作業環境の Neo4j Browser（new-onto-env が表示したポート。例 http://localhost:7574 ）を開き、ユーザー neo4j とパスワードでログインする
     （7474 は原本の Neo4j。Salesforce のデータは入っていない）
  3. 画面上の入力欄に、使いたい番号の枠の中（「// ①」の行から次の「====」の手前まで）を貼り、Ctrl + Enter（または ▶）
  4. 図の丸をクリックすると、右側に物理名・ファイル・行が出る
     - 図の丸は見やすく作り直した「仮の丸」なので、ダブルクリックで広げることはできない（広げたいときは ▼ の値を変えて出し直す）
     - 丸が多すぎて見にくいときは、② の段数を減らす。表で見たいときは、結果の左の「Table」を押す

■ 名前の書き方
  - システム … 取り込んだときの名前（lineage.py export の --repo に渡した識別子）
  - 項目 … 「オブジェクトの表示ラベル.項目の表示ラベル」（例: '商談.金額'）。分からないときは ⓪-1 で探す
  - 機能 … 画面フロー・ボタン・LWC などの表示名（例: '商談を作成'）。分からないときは ⓪-2 で探す

■ 地図に無いもの（図に出ないから「使っていない」とは言えない）
  - 管理パッケージの中身（ソースが見えない）、動的 SOQL・項目名を変数で渡す処理（「未解決」として残る）
  - レコードのデータ（件数・値）。メタデータ（force-app）だけから作っている
  - 細かい読み書きの根拠は、図の丸の「ファイル」「行」でソースを開いて確かめる

================================================================
⓪-1 項目の名前を探す（表で出る）
（探す言葉は表示ラベルでも API 名でもよい）
================================================================

// ⓪-1 項目の名前を探す（表で出る）
// ▼ 調べたい内容に合わせて変える
WITH 'my_project' AS システム, '金額' AS 探す言葉
MATCH (s:cod__Table)-[:cod__hasColumn]->(c:cod__Column)
WHERE c.uri CONTAINS '/code-data/db/' + システム + '/'
  AND (s.表示名 + '.' + c.表示名 CONTAINS 探す言葉 OR head(c.cod__physicalName) CONTAINS 探す言葉)
RETURN s.表示名 + '.' + c.表示名 AS 項目, head(s.cod__physicalName) + '.' + head(c.cod__physicalName) AS API名
ORDER BY 項目 LIMIT 100

// ⓪-2 機能（画面・ボタン・保存・バッチ）の名前を探す（表で出る）
// ▼ 調べたい内容に合わせて変える
WITH 'my_project' AS システム, '商談' AS 探す言葉,
     {cod__Screen: '画面・ボタン', cod__Batch: 'バッチ・スケジュール', cod__ApiEndpoint: 'API', cod__OtherFeature: '保存・承認プロセス'} AS 種類名
MATCH (f)-[:cod__hasEntryPoint]->()

RETURN DISTINCT f.表示名 AS 機能, 種類名[head([l IN labels(f) WHERE 種類名[l] IS NOT NULL])] AS 種類
ORDER BY 種類, 機能 LIMIT 100


================================================================
① オブジェクトを保存すると動くもの（フロー・トリガ・入力規則・項目自動更新と、その先で書き込むオブジェクト）
（呼び出しは3段まで辿る。書き込むオブジェクトの保存でも、また①が動く）
================================================================

// ① オブジェクトを保存すると動くもの（フロー・トリガ・入力規則・項目自動更新と、その先で書き込むオブジェクト）
// ▼ 調べたい内容に合わせて、この2つを変える（オブジェクトは表示ラベル）
WITH 'my_project' AS システム, '商談' AS オブジェクト
WITH 'https://ontology.sodech.co.jp/code-data/' + システム + '/' AS 系, オブジェクト,
     {apex: 'Apex', trigger: 'トリガ', flow: 'フロー', vr: '入力規則', wf: '項目自動更新', formula: '数式項目',
      rollup: '積み上げ集計', lwc: 'LWC', aura: 'Aura', vf: 'Visualforce', action: 'クイックアクション'} AS 種類名
MATCH (f:cod__OtherFeature)-[:cod__hasEntryPoint]->(e)
WHERE f.uri STARTS WITH 系 AND f.表示名 = オブジェクト + 'の保存（保存時に動く処理）'
// 保存で動く処理から呼ばれる処理（3段まで）
OPTIONAL MATCH (e)-[:cod__calls|cod__possiblyCalls*1..3]->(x:cod__Function)
WITH f, 種類名, collect(DISTINCT e) + collect(DISTINCT x) AS fns
UNWIND fns AS fn
// それぞれの処理が書き込むオブジェクト（ほかのオブジェクトの保存につながる）
OPTIONAL MATCH (fn)-[:cod__writesTo]->(t:cod__Table)
OPTIONAL MATCH (fn)-[c:cod__calls|cod__possiblyCalls]->(y:cod__Function) WHERE y IN fns
WITH f, 種類名, fn, collect(DISTINCT t) AS ts, collect(DISTINCT [type(c), y]) AS cs
WITH f, 種類名, collect({fn: fn, ts: ts, cs: cs}) AS rows
WITH f, 種類名, rows,
     [f] + [r IN rows | r.fn] + apoc.coll.flatten([r IN rows | r.ts]) AS ns
UNWIND ns AS n
WITH f, 種類名, rows, collect(DISTINCT n) AS nodes
WITH f, rows, apoc.map.fromPairs([n IN nodes | [elementId(n), apoc.create.vNode(
       [CASE WHEN n = f THEN '保存'
             WHEN n:cod__Table THEN '書き込むオブジェクト'
             ELSE coalesce(種類名[split(head(n.cod__qualifiedName), ':')[0]], '処理') END],
       apoc.map.clean({name: n.表示名, 物理名: head(n.cod__physicalName),
        ファイル: head(n.cod__sourceFile)}, [], [null]))]]) AS vm
UNWIND rows AS r
WITH f, vm, r,
     CASE WHEN EXISTS { (f)-[:cod__hasEntryPoint]->(x) WHERE x = r.fn } THEN [[f, '保存で動く', r.fn]] ELSE [] END
     + [t IN r.ts | [r.fn, '書き込む', t]]
     + [c IN r.cs WHERE c[1] IS NOT NULL | [r.fn, CASE c[0] WHEN 'cod__calls' THEN '呼び出す' ELSE '呼び出す（推定）' END, c[1]]] AS es
UNWIND es AS e
WITH DISTINCT vm, e
RETURN vm[elementId(e[0])] AS a,
       apoc.create.vRelationship(vm[elementId(e[0])], e[1], {}, vm[elementId(e[2])]) AS rel,
       vm[elementId(e[2])] AS b


================================================================
② 項目の流れ（値がどこから来て、どこへ行くか）
（段数 = 転記・計算をいくつ辿るか。条件（IF の判定）に使う流れまで見たいときは、cod__sourceOf の並びに |cod__conditionOf を足す）
================================================================

// ② 項目の流れ（値がどこから来て、どこへ行くか）
// ▼ 調べたい内容に合わせて、この3つを変える（項目は「オブジェクトの表示ラベル.項目の表示ラベル」）
WITH 'my_project' AS システム, '商談.金額' AS 項目, 6 AS 段数
MATCH (s)-[:cod__hasColumn|cod__hasField]->(c)
WHERE c.uri CONTAINS '/code-data/db/' + システム + '/' AND s.表示名 + '.' + c.表示名 = 項目
CALL (c, 段数) {
  // 上流: この項目に値を入れる転記・計算（1段 = 演算1つ）
  MATCH p = (x)-[:cod__sourceOf|cod__operandOf|cod__lookupSourceOf|cod__outputTo*1..12]->(c)
  WHERE length(p) <= 段数 * 2 RETURN p
  UNION
  // 下流: この項目の値を使う転記・計算・画面
  MATCH p = (c)-[:cod__sourceOf|cod__operandOf|cod__lookupSourceOf|cod__outputTo*1..12]->(x)
  WHERE length(p) <= 段数 * 2 RETURN p
}
UNWIND relationships(p) AS r
WITH collect(DISTINCT r) AS rels,
     {cod__Transfer: '転記', cod__Calculation: '計算', cod__Aggregation: '集計', cod__Validation: '入力チェック',
      cod__Column: '項目', cod__ScreenField: '画面で使う項目', cod__InterfaceField: '処理で使う項目'} AS 種類名,
     {cod__sourceOf: '転記元', cod__operandOf: '計算に使う', cod__lookupSourceOf: '参照元', cod__outputTo: '出力先'} AS 関係名
UNWIND rels AS r
UNWIND [startNode(r), endNode(r)] AS n
WITH rels, 種類名, 関係名, collect(DISTINCT n) AS ns
UNWIND ns AS n
OPTIONAL MATCH (st)-[:cod__hasColumn|cod__hasField]->(n)
OPTIONAL MATCH (n)-[:cod__definedIn]->(fn)
WITH rels, 種類名, 関係名, n, st, fn, head([l IN labels(n) WHERE 種類名[l] IS NOT NULL]) AS k
WITH rels, 関係名, apoc.map.fromPairs(collect([elementId(n), apoc.create.vNode(
       [coalesce(種類名[k], 'その他')],
       apoc.map.clean({name: CASE WHEN st IS NULL THEN n.表示名 ELSE st.表示名 + '.' + n.表示名 END,
        物理名: head(n.cod__physicalName), ルール: replace(head(coalesce(n.cod__ruleText, [null])), '@ja', ''),
        処理: fn.表示名, ファイル: head(n.cod__sourceFile), 行: head(n.cod__lineStart)}, [], [null]))])) AS vm
UNWIND rels AS r
RETURN vm[elementId(startNode(r))] AS a,
       apoc.create.vRelationship(vm[elementId(startNode(r))], coalesce(関係名[type(r)], type(r)), {}, vm[elementId(endNode(r))]) AS rel,
       vm[elementId(endNode(r))] AS b

// ③ 項目を変えるとき、どこを見るか（この項目を書く処理・読む処理・条件に使う処理と、それが動く機能）
// ▼ 調べたい内容に合わせて、この2つを変える（項目は「オブジェクトの表示ラベル.項目の表示ラベル」）
WITH 'my_project' AS システム, '商談.金額' AS 項目
MATCH (s)-[:cod__hasColumn|cod__hasField]->(c)
WHERE c.uri CONTAINS '/code-data/db/' + システム + '/' AND s.表示名 + '.' + c.表示名 = 項目
CALL (c) {
  MATCH (op)-[:cod__outputTo]->(c) RETURN op, '書く' AS 使い方
  UNION
  MATCH (c)-[:cod__sourceOf|cod__lookupSourceOf]->(op) RETURN op, '読む' AS 使い方
  UNION
  MATCH (c)-[:cod__operandOf]->(op) RETURN op, '計算に使う' AS 使い方
  UNION
  MATCH (c)-[:cod__conditionOf|cod__lookupConditionOf|cod__lookupKeyOf]->(op) RETURN op, '条件に使う' AS 使い方
}
MATCH (op)-[:cod__definedIn]->(fn)
OPTIONAL MATCH (fn)-[:cod__usedInFeature|cod__possiblyUsedInFeature]->(f)
WITH s, c, fn, collect(DISTINCT 使い方) AS 使い方, collect(DISTINCT f) AS fs,
     {apex: 'Apex', trigger: 'トリガ', flow: 'フロー', vr: '入力規則', wf: '項目自動更新', formula: '数式項目',
      rollup: '積み上げ集計', lwc: 'LWC', aura: 'Aura', vf: 'Visualforce', action: 'クイックアクション'} AS 種類名
WITH s, c, collect({fn: fn, u: 使い方, fs: fs, k: 種類名[split(head(fn.cod__qualifiedName), ':')[0]]}) AS rows
WITH c, rows, apoc.create.vNode(['起点の項目'], {name: s.表示名 + '.' + c.表示名, 物理名: head(c.cod__physicalName)}) AS cv
UNWIND rows AS r
WITH cv, r, apoc.create.vNode([CASE WHEN '書く' IN r.u THEN '書く処理' ELSE '使う処理' END],
       apoc.map.clean({name: r.fn.表示名, 種類: r.k, 物理名: head(r.fn.cod__physicalName),
        ファイル: head(r.fn.cod__sourceFile)}, [], [null])) AS fv
UNWIND [[cv, apoc.text.join(r.u, '・'), fv]] + [f IN r.fs | [fv, '動く機能', apoc.create.vNode(['機能'], {name: f.表示名, uri: f.uri})]] AS e
RETURN e[0] AS a, apoc.create.vRelationship(e[0], e[1], {}, e[2]) AS rel, e[2] AS b

// ④ 画面・ボタンから動く処理と、読み書きするオブジェクト
// ▼ 調べたい内容に合わせて、この2つを変える（機能は画面フロー・ボタンの表示ラベル、または LWC・Visualforce の名前）
WITH 'my_project' AS システム, '商談を作成' AS 機能
MATCH (f)-[:cod__hasEntryPoint]->(e)
WHERE f.uri STARTS WITH 'https://ontology.sodech.co.jp/code-data/' + システム + '/' AND f.表示名 = 機能
OPTIONAL MATCH (e)-[:cod__calls|cod__possiblyCalls*1..3]->(x:cod__Function)
WITH f, collect(DISTINCT e) + collect(DISTINCT x) AS fns,
     {apex: 'Apex', trigger: 'トリガ', flow: 'フロー', vr: '入力規則', wf: '項目自動更新', formula: '数式項目',
      rollup: '積み上げ集計', lwc: 'LWC', aura: 'Aura', vf: 'Visualforce', action: 'ボタン'} AS 種類名
UNWIND fns AS fn
OPTIONAL MATCH (fn)-[a:cod__writesTo|cod__readsFrom]->(t:cod__Table)
OPTIONAL MATCH (fn)-[c:cod__calls|cod__possiblyCalls]->(y:cod__Function) WHERE y IN fns
WITH f, 種類名, fn, collect(DISTINCT [type(a), t]) AS ts, collect(DISTINCT [type(c), y]) AS cs
WITH f, collect({fn: fn, ts: ts, cs: cs}) AS rows, 種類名
WITH f, rows, 種類名, [f] + [r IN rows | r.fn] + [x IN apoc.coll.flatten([r IN rows | [t IN r.ts | t[1]]]) WHERE x IS NOT NULL] AS ns
UNWIND ns AS n
WITH f, rows, 種類名, collect(DISTINCT n) AS nodes
WITH f, rows, apoc.map.fromPairs([n IN nodes | [elementId(n), apoc.create.vNode(
       [CASE WHEN n = f THEN '画面・ボタン'
             WHEN n:cod__Table THEN 'オブジェクト'
             ELSE coalesce(種類名[split(head(n.cod__qualifiedName), ':')[0]], '処理') END],
       apoc.map.clean({name: n.表示名, 物理名: head(n.cod__physicalName), ファイル: head(n.cod__sourceFile)}, [], [null]))]]) AS vm
UNWIND rows AS r
WITH f, vm, r,
     CASE WHEN EXISTS { (f)-[:cod__hasEntryPoint]->(x) WHERE x = r.fn } THEN [[f, '動かす', r.fn]] ELSE [] END
     + [t IN r.ts WHERE t[1] IS NOT NULL | [r.fn, CASE t[0] WHEN 'cod__writesTo' THEN '書き込む' ELSE '読む' END, t[1]]]
     + [c IN r.cs WHERE c[1] IS NOT NULL | [r.fn, CASE c[0] WHEN 'cod__calls' THEN '呼び出す' ELSE '呼び出す（推定）' END, c[1]]] AS es
UNWIND es AS e
WITH DISTINCT vm, e
RETURN vm[elementId(e[0])] AS a,
       apoc.create.vRelationship(vm[elementId(e[0])], e[1], {}, vm[elementId(e[2])]) AS rel,
       vm[elementId(e[2])] AS b


================================================================
⑤ オブジェクトの関係図（参照・主従。矢印は「参照する側 → 参照先」）
（線は onto_env.py load が取り込みのあとに足したもの。共通基盤の語彙にはオブジェクトどうしの参照が無いため）
================================================================

// ⑤ オブジェクトの関係図（参照・主従。矢印は「参照する側 → 参照先」。同じオブジェクトどうしの線は1本にまとめ、線をクリックすると全部の項目が出る）
// ▼ 調べたい内容に合わせて、この3つを変える（オブジェクトは表示ラベル。'' にするとシステム全体。段数 = 何つ先のオブジェクトまで出すか）
WITH 'my_project' AS システム, '商談' AS オブジェクト, 1 AS 段数
WITH 'https://ontology.sodech.co.jp/code-data/db/' + システム + '/' AS 系, オブジェクト, 段数
OPTIONAL MATCH (s:cod__Table) WHERE s.uri STARTS WITH 系 AND s.表示名 = オブジェクト
CALL (s, 段数) {
  WITH s WHERE s IS NOT NULL
  CALL apoc.path.subgraphNodes(s, {relationshipFilter: 'cod__hasColumn|sf__referenceTo', maxLevel: 段数 * 2}) YIELD node
  RETURN collect(node) AS ns
}
MATCH (t:cod__Table)-[:cod__hasColumn]->(c:cod__Column)-[:sf__referenceTo]->(t2:cod__Table)
WHERE t.uri STARTS WITH 系 AND (オブジェクト = '' OR (t IN ns AND t2 IN ns AND (段数 > 1 OR t = s OR t2 = s)))
WITH s, t, t2, collect(c) AS cs
WITH s, collect({a: t, b: t2, cs: cs}) AS es
WITH s, es, apoc.coll.toSet(apoc.coll.flatten([e IN es | [e.a, e.b]])) AS tables
WITH es, apoc.map.fromPairs([t IN tables | [elementId(t), apoc.create.vNode(
       [CASE WHEN t = s THEN '起点のオブジェクト' ELSE 'オブジェクト' END],
       {name: t.表示名, 物理名: head(t.cod__physicalName)})]]) AS vm
UNWIND es AS e
WITH vm, e, apoc.coll.sort([c IN e.cs | c.表示名]) AS names, any(c IN e.cs WHERE head(c.cod__dataType) = 'MasterDetail') AS md
RETURN vm[elementId(e.a)] AS a,
       apoc.create.vRelationship(vm[elementId(e.a)],
         CASE WHEN size(names) <= 2 THEN apoc.text.join(names, '・') ELSE names[0] + ' ほか' + toString(size(names) - 1) + '項目' END
           + CASE WHEN md THEN '（主従）' ELSE '（参照）' END,
         {項目: apoc.text.join([c IN e.cs | c.表示名 + '（' + head(c.cod__physicalName) + '）'], '、'), 本数: size(e.cs)},
         vm[elementId(e.b)]) AS rel,
       vm[elementId(e.b)] AS b


================================================================
⑥ 項目まわりの地図（その項目を書く・読む・条件に使う自動処理と画面、それが動く場所、値の出どころと波及先の項目）
（処理の丸をクリックすると、いつ動くか・有効か・開始条件・設定する値・呼ばれ方などが出る。性質は onto_env.py load が取り込みのあとに足したもの）
================================================================

// ⑥ 項目まわりの地図（その項目を書く・読む・条件に使う自動処理と画面、それが動く場所、値の出どころと波及先の項目。処理の丸をクリックすると、いつ動くか・有効か・開始条件などが出る）
// ▼ 調べたい内容に合わせて、この2つを変える（項目は「オブジェクトの表示ラベル.項目の表示ラベル」）
WITH 'my_project' AS システム, '商談.金額' AS 項目
MATCH (s:cod__Table)-[:cod__hasColumn]->(c:cod__Column)
WHERE c.uri CONTAINS '/code-data/db/' + システム + '/' AND s.表示名 + '.' + c.表示名 = 項目
// この項目に触る演算と、その使い方
CALL (c) {
  MATCH (op)-[:cod__outputTo]->(c) RETURN op, '書く' AS how
  UNION
  MATCH (c)-[r]->(op) WHERE type(r) IN ['cod__sourceOf', 'cod__lookupSourceOf'] RETURN op, '読む' AS how
  UNION
  MATCH (c)-[:cod__operandOf]->(op) RETURN op, '計算に使う' AS how
  UNION
  MATCH (c)-[r]->(op) WHERE type(r) IN ['cod__conditionOf', 'cod__lookupConditionOf', 'cod__lookupKeyOf'] RETURN op, '条件に使う' AS how
}
MATCH (op)-[:cod__definedIn]->(fn:cod__Function)
// 値の出どころ（この項目に書く演算の写し元）と、波及先（この項目を使う演算が書く、ほかの項目）
OPTIONAL MATCH (src:cod__Column)-[:cod__sourceOf|cod__operandOf]->(op) WHERE how = '書く' AND src <> c
OPTIONAL MATCH (op)-[:cod__outputTo]->(dst:cod__Column) WHERE how IN ['読む', '計算に使う'] AND dst <> c
WITH c, fn, collect(DISTINCT how) AS hows, collect(DISTINCT src) AS srcs, collect(DISTINCT dst) AS dsts
OPTIONAL MATCH (fn)-[:cod__usedInFeature]->(f)
WITH c, fn, hows, srcs, dsts, collect(DISTINCT f) AS fs
WITH c, collect({fn: fn, hows: hows, srcs: srcs, dsts: dsts, fs: fs}) AS rows
// 線（同じ丸は1つにまとめる）
WITH c, apoc.coll.flatten([r IN rows | r.dsts]) AS dsts, apoc.coll.toSet(apoc.coll.flatten([r IN rows |
       [CASE WHEN r.hows = ['書く'] THEN [r.fn, '書く', c] ELSE [c, apoc.text.join(r.hows, '・'), r.fn] END]
       + [f IN r.fs | [r.fn, '動く場所', f]] + [x IN r.srcs | [x, '値の出どころ', r.fn]] + [x IN r.dsts | [r.fn, '書く', x]]], false)) AS es
WITH c, dsts, es, apoc.coll.toSet(apoc.coll.flatten([e IN es | [e[0], e[2]]])) AS ns
UNWIND ns AS n
OPTIONAL MATCH (t:cod__Table)-[:cod__hasColumn]->(n)
WITH c, dsts, es, n, t
WITH es, apoc.map.fromPairs(collect([elementId(n), apoc.create.vNode(
       [CASE WHEN n = c THEN '起点の項目'
             WHEN n:cod__Function THEN split(coalesce(n.種類, '処理'), '（')[0]
             WHEN n:cod__Column AND n IN dsts THEN '波及先の項目'
             WHEN n:cod__Column THEN '値の出どころの項目'
             WHEN n:cod__OtherFeature AND n.表示名 CONTAINS '承認プロセス' THEN '承認プロセス'
             WHEN n:cod__OtherFeature THEN '保存' WHEN n:cod__Batch THEN 'バッチ' WHEN n:cod__ApiEndpoint THEN 'API'
             ELSE '画面・ボタン' END],
       apoc.map.merge(apoc.map.clean({name: CASE WHEN t IS NULL THEN n.表示名 ELSE t.表示名 + '.' + n.表示名 END,
                       物理名: CASE WHEN t IS NULL THEN head(coalesce(n.cod__qualifiedName, n.cod__physicalName)) ELSE head(t.cod__physicalName) + '.' + head(n.cod__physicalName) END,
                       種類: n.種類, 動く時: n.動く時, 状態: n.状態, 開始条件: n.開始条件, 設定する値: n.設定する値, 呼ばれ方: n.呼ばれ方,
                       説明: n.説明, データ型: head(n.cod__dataType), ファイル: head(n.cod__sourceFile)}, [], [null]),
       // 組織での最終更新（lineage.py modified で取ってあれば。キーは「最終更新（本番）」「最終更新（Sandbox の別名）」）
       apoc.map.fromPairs([k IN keys(n) WHERE k STARTS WITH '最終更新' | [k, n[k]]])))])) AS vm
UNWIND es AS e
RETURN vm[elementId(e[0])] AS a, apoc.create.vRelationship(vm[elementId(e[0])], e[1], {}, vm[elementId(e[2])]) AS rel, vm[elementId(e[2])] AS b
